# 主动推荐信号治理

治理用户主动推荐信号，并据此审查创作者扶持与长期效果。

## 业务事实

- 平台已与数百个资源单位合作提供稀缺创作场景
- 参与者包括科研学者与多种小众职业创作者
- 优质内容会继续进入营销撮合与商业履约

## 协作角色

- 创作者
- 资源单位
- 平台运营
- 品牌与权利审查人员

## 目录说明

- `contracts/domain.schema.json` 定义共享资料的字段与基本约束。
- `fixtures/context.json` 提供不含真实个人信息的公开样例。
- `fixtures/authors.json` / `fixtures/works.json` / `fixtures/events.json` 提供作者阶段、创作场景与推荐事件的公开样例（标识均为化名）。
- `src/` 为治理服务实现：
  - `events.js` 推荐事件台账：校验、同一用户或设备重放去重、撤销保留。
  - `windows.js` 统计窗口聚合，区分自然分享、活动任务与付费分发。
  - `risk.js` 风险模型，只产出「待复核」标记。
  - `review.js` 人工复核与申诉，判断日志只增不删。
  - `eligibility.js` 扶持资格冻结与恢复、扶持决定与理由链。
  - `lookback.js` 扶持前后持续创作与真实受众留存对比。
  - `access.js` 角色化数据投影，敏感关系数据仅供授权角色。
  - `service.js` 串联上述能力的治理服务门面，启动时逐项校验领域约束均有对应能力。

## 治理流程

1. 推荐事件进入台账，保留推荐发生时的作品版本、入口、观看深度、用户关系与撤销状态；同一用户或设备对同一作品的重放只计第一次。
2. 关闭统计窗口时聚合有效推荐并运行风险模型；命中协同特征即开出「待复核」标记并自动冻结当期扶持资格，风险模型本身不作任何处置。
3. 人工复核确认异常则当期资格取消；复核排除或申诉成立则恢复权益，旧判断保留在复核日志中，不删除。
4. 扶持决定只依据去重后的自然分享计量，并按作者阶段与小众专业赛道调整门槛；决定附完整理由链，运营可逐条解释一次扶持为何成立。
5. 扶持后通过效果回看比较前后窗口的持续创作与真实受众留存，验证扶持是否成立。

## 角色与敏感数据

- 平台运营、品牌与权利审查人员、审计员：只能看到脱敏投影（用户与设备标识打码，不含用户关系）。
- 风控审查员（授权）：可查看用户关系与设备标识，用于复核与申诉裁定。

## 本地检查

运行 `npm test` 可确认样例能够读取，领域标识、版本、参与者和记录结构完整，并覆盖事件去重、窗口聚合、风险标记、复核申诉、资格冻结、效果回看与访问控制。样例中不包含账号、密钥或连接凭据。
